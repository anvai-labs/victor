# U9 — Contracts & verticals (`victor-contracts/`, `verticals/*`)

331 modules / 109,763 LOC / 673 churn commits (12m). Reviewer: parallel unit review, 2026-09-03.

## Overview
The contracts↔verticals split is architecturally real (bidirectional AST guards, optional `victor-ai` deps, lazy PEP 562 bridges) but **under-enforced**: `make check-vertical-boundaries` passes while 15+ production lazy imports of host internals (`victor.config/tools/storage/observability`) evade the auditor's prefix list. `PluginContext` is accreting (20 methods, 4 deprecated) with capability negotiation done by hasattr probes, and the register(context) consolidation seam is bypassed by 19 sidecar entry-point groups. The 4 small verticals are ~73% template-copied scaffolding whose dedup abstraction (`victor/contrib`) sits on the wrong side of the boundary. victor-coding is well-subpackaged but carries 3-4k-line tool monoliths.

## Co-design opportunities
1. Single boundary manifest: publish the forbidden/allowed prefix table from `victor_contracts.constants`; contract_audit.py + both guard tests import it — closes F1/F6 in one move and gives external vertical authors the same linter locally (`victor-contracts check` already exists).
2. Contracts-side settings/config bridge: `victor_contracts.config_runtime` exposing get_project_paths/load_settings lazily, generalizing victor-coding's compat/settings.py chain; removes the largest class of `victor.config` leaks.
3. Version-declared capability negotiation: replace hasattr probing with the existing `CapabilityContract.min_sdk_version` + `CURRENT_API_VERSION=2` machinery — the seam exists, it's just not what the hot path uses.
4. Promote contrib bases to contracts (F5): the single highest-leverage dedup; scaffold_vertical.py should emit contract-based implementations, not copies.
5. Bridge drift CI: a test asserting every `_LAZY_IMPORTS` target resolves against the current host (15 bridges × ~10 symbols) — today a host rename breaks verticals only at runtime AttributeError.
6. Team-spec group unification: deprecate one of the two competing entry-point groups per the CONTRACT_STABILITY policy.

## Keep intact
- Lazy PEP 562 bridges (`_LAZY_IMPORTS` + module `__getattr__`): module import stays host-free (measured 0.125s import, 70 modules) — the right pattern for the host-required tier.
- victor_sdk meta-path alias (victor_sdk/__init__.py:44-66): aliases the *same module objects*, preserving isinstance identity across old/new names; deprecation warnings verified firing.
- Bidirectional guards with stale-baseline enforcement (test_core_vertical_import_boundary.py:229, dynamic-import detection :85) — core↔vertical decoupling genuinely held at zero violations.
- victor-ai as optional `runtime` extra in all 5 verticals + audit error on required victor-ai dep — keeps verticals publishable standalone.
- graph_tool.py start-time bridge validation (:39-55) — good degradation behavior for host-version skew.
