# U6 — Workflows, teams, coordination & protocols

134 modules / 73,211 LOC / 1,220 churn commits (12m). Reviewer: parallel unit review, 2026-09-03.

## Overview
`workflows` is the bulk (99 files, 56k LOC) carrying the compiler+engine plus accreted peripheral features (scheduler, deployment, credentials, generation, metrics); `teams`+`coordination` implement the formations law well (coordinator-as-node is real); `protocols` is a domain grab-bag. The central defect is **engine duality**: the hand-rolled BFS `WorkflowExecutor` and the StateGraph path are both live in production, with divergent parallel-failure, caching, and checkpoint semantics. Second theme: everything is recompiled/revalidated/re-deep-copied per run — the "caches" cache the cheap artifact (parsed YAML), never the expensive one (CompiledGraph, state). ADR-023 durability is well built but concentrated 59 commits of churn into one 3,404-line god-file.

## Co-design opportunities
1. Compile-once/execute-many artifact: one CompiledGraph cache keyed by definition hash + factory version, shared by WorkflowEngine, API routes, and the TUI (all three currently construct their own compiler+executor per request).
2. Typed team-result channel: a `team` channel with per-key reducers on WorkflowStateModel lets the graph engine share instead of copy (vs today's full-result dict into `team_output` at unified_coordinator.py:3386-3395).
3. One parallel dataflow: single channel/reducer core makes formations trivially expressible as node functions over the same semantics (FEP).
4. Unified checkpoint record: three checkpoint shapes today — graph `WorkflowCheckpoint`, ADR-023 team member checkpoints, HITL `StoredRequest` (hitl_api.py:106). One envelope (thread, node/member, resume-at, payload) fixes F4's confusion.
5. Prefix-cache-aware member hand-offs: sequential formation passes `previous_output` as one blob (formations/sequential.py:84-104); co-design with provider KV-prefix caching (frozen system prompt, delta-only user turns) so member B's prompt extends A's prefix.
6. Protocols consolidation into victor_contracts, enabling F1 engine unification without breaking external implementers.

## Keep intact
1. `UnifiedTeamCoordinator.__call__` + `StateGraphNodeConfig` key remapping (unified_coordinator.py:3204-3404) — the law-compliant node interface; formation_strategy injects a hint and never mutates `self._formation` (concurrency-safe).
2. ContextVar-scoped `_CoordinatorExecutionState` (:127-134, 283-286) — per-call state without locks; the concurrency model ADR-023 correctly built on.
3. ADR-023 opt-in hooks on `TeamContext` (formations/base.py:92-119): default-None so non-durable runs are byte-identical — preserve the null-default discipline in any extraction.
4. Definition cache keying by `path+name+config_hash+mtime` (cache.py:798-812) — clean invalidation primitive; extend it to the CompiledGraph cache.
5. `CopyOnWriteState` owner thread/task guard and COW-by-default (graph_state.py:51-90) — load-bearing for state isolation.

## Quick metrics
- unified_coordinator.py = 3,404 LOC, 59 churn commits/12mo — 33% of teams+coordination LOC in one file.
- Executor sprawl: 19 modules define `*Executor` classes; 3 self-declared shims; `victor/workflows/__init__.py` exports 228 names.
- Engine split (live call sites): legacy BFS executor → API routes, mode_workflows, workflow_service_provider, agent/specs/converter (4); StateGraph → ui/commands/chat, workflows/runtime, deployment (3).
- Deep-copy density: 1 per node (state_history, zero internal readers), 1 per parallel branch ×2 mechanisms, 2-6 per team delegate run.
- Dead-in-prod: adapters.py (486) + metrics.py (869), 14 churn commits each; chain handler raises NotImplementedError, only tests exercise it.
- hitl_api.py: 47% inline HTML; duplicate `IWorkflowExecutor` protocols at two paths.
- Framework→workflows inversion: `victor/framework/workflow_engine.py` and `framework/coordinators/*` import `victor.workflows.*` (workflow_engine.py:95-100) — the "stable framework layer" engine delegates to 56k LOC of internals.
