# U5 — Storage, core, state & victor-codegraph

313 modules / 111,994 LOC / 2,579 churn commits (12m). Reviewer: parallel unit review, 2026-09-03. Metrics gathered during a live reindex (consistent-snapshot where noted).

## Overview
Layered cleanly (Infrastructure) and the recent graph-backend work (#873–#915) shows real co-design discipline. The dominant weaknesses are on the **default SQLite path**: (1) the incremental machinery does not actually amortize parsing — one changed file triggers a full single-threaded `parse_repo` pass; (2) `project.db` is a derived, rebuildable artifact that grows to its churn high-water mark and never reclaims (2.64 GB measured, no auto-vacuum in the file header, manual-only `maintain()`); (3) per-node/per-file round trips survive on SQLite that were already batched on Proxima. Protocol/backend capability drift is the main structural debt.

## Co-design opportunities
1. Manifest-aware `parse_repo` (victor-codegraph × Victor indexer × ProximaDB SDK): accept a previous manifest, parse only added/changed, reuse prior `ParsedCode` — fixes U5-02 for all three consumers at the ADR-014 boundary.
2. One staleness primitive on the protocol: `get_staleness(files) → {file: (mtime, hash)}` batched per backend — removes the N+1 and the `getattr` probing.
3. Tier-A/B parity on SQLite: port `cpg_fragments` tiering; 1.10 M statement nodes leave `graph_node`, its 5 indexes and FTS (~700+ MB), aligning hot-graph size across backends.
4. Derived-state lifecycle ownership: rebuild completion implies reclamation (auto incremental_vacuum + WAL truncate) instead of a manual CLI.
5. Batched node-metadata persistence seam: protocol `update_nodes_metadata(pairs)` per backend; `_generate_embeddings` stops feature-probing; SQLite stops paying a transaction per node.
6. One connection owner per DB file: conversation persistence through ProjectDatabaseManager so busy_timeout, WAL pragmas, FK enforcement, migrations are uniform.

## Keep intact
1. Legacy calls fallback (`_build_calls_edges_legacy`, indexing.py:2664; provider fallback 1680-1740) — explicitly load-bearing; only path with symbols when no enhanced TSA provider registers.
2. Self-heal schema re-ensure at index start (indexing.py:460-470) — compensates for the intentionally non-atomic DROP/CREATE truncate; do not "fix" the truncate into a slow DELETE.
3. Provider resolution before the parallel parse burst (indexing.py:481-490) — reordering reintroduces the documented race where 51/92 files silently lost IMPORTS edges.
4. Edge endpoint integrity drop (`_drop_dangling_edge_rows`, sqlite_store.py:432-470) — keeps SQLite and ORION producing identical graphs.
5. Deliberate `busy_timeout=5000` divergence (database.py:1642-1646) and the separate undo.db — intentional drop-not-fail policy for non-critical writers.
