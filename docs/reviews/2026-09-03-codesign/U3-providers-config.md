# U3 — Providers & config (`victor/providers/` + `victor/config/`)

134 modules / 41,015 LOC / 1,660 churn commits (12m). Reviewer: parallel unit review, 2026-09-03.

## Overview
The 25-adapter story is better than the file count suggests: since TD-0002, most adapters are thin policy shells (xai 32 LOC, zai 99, deepseek 140) over a genuine kernel+dialect core (`HttpxOpenAICompatProvider` payload/parse template + `SandhiTypedProviderMixin` transport); only 6-7 "native-only" adapters still own raw HTTP. The recent sandhi idempotency work (#991/#992) is correct and verified. The real debt is concentrated in: an uncached `Settings()` god-module that gets re-built per LLM request, an Infrastructure→Runtime layering leak nothing guards, and three uncoordinated retry/circuit layers whose defaults contradict each other.

## Co-design opportunities
1. Config snapshot ⇄ streaming-first runtime: immutable per-session settings snapshot (config exports once; providers receive at construction).
2. One retry owner: Rust sandhi handle retries transport blips; Python owns logical fallback; delete the base wrapper once native-only adapters migrate.
3. Failure taxonomy as a shared kernel type consumed by classification, retryability, and health scoring (smart_router._score_health).
4. Cache-economics → timeout co-design: extend the `CacheCostModel` value-object pattern (base.py:149-179) to a `TimeoutProfile`.
5. Kernel+dialects completion: port azure/vertex/huggingface to the policy-shell pattern or formally freeze them as tier-3 (ADR-029).
6. Settings aggregation as data: declarative registry for 46 groups + 147 env mappings.

## Keep intact
1. Chat-only idempotency binding (resilience.py:803-811; streams deliberately do not bind — :957-968 documents the async-generator ContextVar leak). Verified: retries AND fallbacks of one logical call share the key. Do not "fix" the stream asymmetry.
2. Session affinity in neutral metadata, never the body (sandhi_transport.py:530-537) — preserves prompt-cache byte-stability and vendor KV-cache mapping.
3. No silent transport fallback (sandhi_transport.py:88-109) — missing binding is an installation error; replaying after FFI failure can duplicate billed requests.
4. Ollama `_get_client` event-loop recreation (ollama_provider.py:125-141) — handles run_sync-created loops; removing the loop-id check resurrects the dead-pool failures (#490 cluster).
5. `aclosing` discipline on stream chains (base.py:946-948, resilience.py:999) — the GC-driven GeneratorExit spam fix.
