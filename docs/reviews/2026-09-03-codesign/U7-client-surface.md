# U7 — Client surface (`victor/ui/`, `victor/integrations/`, vscode-victor, web/)

200 modules / 74,090 LOC (Python) + 23,226 LOC TS / 2,211 churn commits (12m). Reviewer: parallel unit review, 2026-09-03.

## Overview
Five live frontends (REPL, Textual TUI, Chainlit, FastAPI/WS/SSE, MCP) over one `VictorClient` seam — the TUI/Chainlit path uses it cleanly (`stream()` + shared `map_event`), but the CLI REPL, `/completions`, MCP server, and several routes bypass it. The streaming renderer is genuinely co-designed (incremental HEAD/TAIL, throttling, bounded buffers); the weak points are the API auth seam (3 call sites across 19 route files), an unshaped API chat contract (no session, history dropped), and dead parallel command systems. Churn concentrates in `commands/chat.py` (112 commits, 3,873 LOC) which is both the hotspot and the biggest bypass.

## Co-design opportunities
1. One event wire contract: extend the typed RenderAction set (already shared by TUI+Chainlit via `map_event`) to API SSE/WS and MCP; retire `_RenderChunk` metadata dicts from anything crossing a process boundary.
2. Session-aware client seam: `session_id` on `VictorClient.chat/stream` + bounded client pool — vscode, web/server, and `/hitl` converge on `resume_session` instead of three ad-hoc hydrations.
3. Auth as infrastructure, not convention: router-level dependency + WS accept-time auth co-designed with the FEP-0020 attribution join so `client_id` flows to every endpoint.
4. Status segment shared by both renderers: `_status_widget` mirrors `_build_cli_runtime_segment` (live_renderer.py:99-103) — extract one per-turn-cached provider.
5. Startup budget as a gate: CI check that `import victor.ui.cli` stays under an importtime threshold — the client's roofline is process startup and nothing measures it.
6. Contract-first vscode: emit OpenAPI at build time and generate `victorClient.ts` models; drift becomes mechanical.

## Keep intact
- `LiveDisplayRenderer` incremental HEAD/TAIL render with content-keyed cache, 50k/10k buffer caps, nested pause depth counting, 10fps tool-progress throttle (live_renderer.py:63-65, 133-174, 653-678) — correct render-bound co-design.
- `EventBridge`/`DeliveryEngine` loop-rebind hygiene (stop() dropping loop-bound queues/tasks, start() backfilling — event_bridge.py:416-476) — load-bearing for test isolation; any queue-bounding change must preserve it.
- `_resolve_stream_factory` duck-typing (handler.py:26-44) — the compatibility seam letting oneshot pass the client while the REPL passes the agent; remove only together with F6.
- The slash registry/protocol pair (fan_in=24 each) — protocol-driven, alias/category-aware, stable; the eager-import issue is in `slash/__init__.py`, not the registry design.
- FastAPI secure CORS defaults and lifespan-managed bridge shutdown (fastapi_server.py:515-537, 571-602).

## Quick metrics
- Auth coverage: `_verify_api_key` called in 3 places, all in chat_routes.py; 0 in the other 18 route files; WS `chat` branch never reads `ws.state.authenticated`.
- Startup: `python -X importtime -c "import victor.ui.cli"` = 1.73s cumulative; 731ms under `victor.ui.commands.benchmark` alone (via slash/__init__.py:71).
- Layering: 56 `victor.agent.*` import sites in `victor/ui` (16 files), 20 in `victor/integrations` (9 files); guard scans 3 directories, misses integrations entirely.
- Dead code: 2,821 LOC (chat_lazy 205 + chat_refactored 283 + optimization 1,262 + victor/commands 1,071) referenced only by one unit test.
- Queue bounds: 0 bounded queues in event_bridge.py (2 unbounded; 2 unreachable QueueFull handlers).
- Wire contract: `ChatRequest` has 1 field; 0 session fields; 1 cached VictorClient per process.
