# U10 — Evaluation, observability, experiments, benchmark & contrib

210 modules / 79,702 LOC / 1,512 churn commits (12m). Reviewer: parallel unit review, 2026-09-03.

## Overview
evaluation/ (39k) and observability/ (24k) carry the weight; contrib/ is actually only 4.9k LOC of vertical base classes (null-object impls consumed by `core/bootstrap.py`). The judge-independence program left ~2.5k LOC of concluded research scaffolding plus ~1.4k LOC of negative-A/B effect-gate aftermath. The strongest live designs are the runtime_feedback trust model, run_kind tagging, and the acceptance-oracle/flag-graduation policy; the weakest spots are a parallel agent-creation path in the churn-leader adapter, synchronous per-event disk writes on the chat hot path, and three overlapping benchmark execution stacks.

## Co-design opportunities
1. One batched observability sink: EnhancedUsageLogger as an ObservabilityBus exporter behind the existing `BufferedExporter` — metrics collector, RL trace-miner, and dashboard share one I/O cadence (F2/F10).
2. (task, agent-config) hash as the single cache/resume key across harness checkpoints, flag_ab arms, and prompt-candidate runs (F4).
3. Converge the YAML benchmark vertical onto the BenchmarkRunner protocol so both stacks exercise `Agent.create` via AgentFactory identically (F1/F8).
4. run_kind-gated payload detail: the contextvar already distinguishes evaluation/delegate/interactive; extend from a label to a policy on content volume (F14).
5. Verifier-vs-X agreement tool: replace the calibration-judge family with one parameterized agreement report (judge injected, verifier as gold) so the negative-evidence dataset stays reusable (F5).
6. Joint schema ownership: add the acceptance oracle as a streaming consumer of per-task events so eval progress is observable without reading checkpoint files (F3).

## Keep intact
1. runtime_feedback source-trust + freshness half-lives (runtime_feedback.py:26-45) — consumed by agent/services/runtime_intelligence.py:31; the joint producer/consumer schema, load-bearing for RL attribution.
2. run_kind contextvar tagging (harness.py:1275 `run_kind_scope(RunKind.EVALUATION)`) — fixed a ~2x eval-share misclassification; every new runner must keep tagging.
3. `flag_graduation.assess_graduation` (flag_graduation.py:81-140) — safety AND benefit policy (#861); generic infra per_turn_auditor graduation still needs; do not delete with the effect-gate cleanup.
4. EvalContainer persistent per-task lifecycle (container_eval.py:255-261) + stale-sandbox sweep (#877) + deterministic image names (#868) — container reuse at the correct granularity.
5. ObservabilityBus lossy contract — AT_MOST_ONCE, `get_delivery_pressure_stats`, `register_drop_alert_handler` (backends.py:1095-1129); dropped-spans-not-blocking is the right behavior; sandhi_meter's default-off optional bridge likewise.
