# U4 — Tools (`victor/tools/` + tool execution seam)

136 modules / 56,024 LOC / 1,538 churn commits (12m). Reviewer: parallel unit review, 2026-09-03.

## Overview
victor/tools is a mature infrastructure layer whose per-tool ergonomics (the `@tool` decorator, schema-level tiers, folding) are genuinely good: schemas are built once at decoration time and metadata precedence is unified through `resolve_contract`. The problems are at the seams: the expensive work (schema generation, embedding, validation) is cached at the layer that nothing calls, while the real hot paths (per-turn selection, per-call execution) re-derive everything; and registration coherence rests on four-plus discovery mechanisms plus duplicated hand-maintained exclusion lists. Subprocess lifecycle handling (no process-group kill, buffer-then-truncate) is the main robustness gap. Churn leaders include two fully dead modules, and jira/slack/teams SaaS tools violate the "root stays generic" rule.

## Co-design opportunities
1. Schema/token snapshot at the consumption seam (with agent/services): (tool, tier)→schema/token-estimate cache keyed by registry version; retire or consume `registry.get_tool_schemas` (F1).
2. One serialization seam for tool results (with pipeline): agree a single orjson-based dict→LLM-text contract; today `original_result` uses `str()` repr (tool_executor.py:1002) and previews re-`str()` twice (tool_pipeline.py:2302, 3205).
3. Shared subprocess runner contract: process groups, incremental capped reads, partial-output-on-timeout — fixes F2/F3 for both owners at once.
4. Embedding-provider parity: lift caching into `_get_embedding` or expose batch-embed on the embeddings service (F4, F8).
5. Registration as one mechanism: entry points + explicit module registry; consolidate the 5 discovery mechanisms. Registry-shape changes are FEP-worthy (fan_in=48).
6. Validator/schema precompile in BaseTool or decorator (F6) — private cache needs no FEP; signature changes do.

## Keep intact
1. mtime-validated FileContentCache + read-tracking (filesystem.py:279-344, 564-615), cleared after non-readonly shell commands (bash.py:1955-1965) — load-bearing locality.
2. Tool folding (folding.py, 24 folds): folded tools stay executable while hidden from advertised schemas — deliberate token economy; do not "fix" by unregistering.
3. `resolve_contract` weak-ref autogen cache (contract.py:39-91) — single metadata-precedence authority.
4. Decorator-time schema build (decorators.py:661-836) — the right amortization pattern; extend it rather than adding per-call caches.
5. ShellCommandCache per-command-prefix TTLs (shell_command_cache.py:55-93), readonly-only caching.
