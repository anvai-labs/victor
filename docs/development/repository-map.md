## Maintenance rule

When a bounded task lands, update its canonical ledger and retain the PR/commit,
acceptance boundary and failed evidence. Remove superseded one-time instructions
only after transferring unresolved items to an existing owner and rewriting all
inbound links, navigation and source comments. Link immutable Git history for
full provenance instead of keeping duplicate active files. Do not delete a draft
proposal, migration guide, fixture README or operational recipe merely because
it is old or has no navigation entry.

Refresh this inventory when adding/removing a source package or documentation
owner: use `git ls-files` for tracked inputs (plus staged additions), group source
directories by the areas above, and check every resulting path. Run the existing
MkDocs build, built-site link checker and repository hygiene checks. Never mark
a module complete solely because its files or tests exist.
